本地 AI 应用会把你的数据发到网上吗？我们在 Mac 上监测了 Ollama、LM Studio 和 Pinku

聊天过程中，三款应用都没有建立任何互联网连接。聊天之外就不一样了：每款应用在打开或下载模型时都会连接自己的服务器，其中一款闲置时也会。以下是我们看到的、测量方法，以及我们看不到的部分。

Maruta G · 2026年10月20日 · English · Русский

简短回答

聊天时什么都没有发送。三款应用在提问和回答期间都没有建立任何到 Mac 之外的连接。网络流量发生在聊天之外：

  • 下载模型一定要联网，这在意料之中：连接 Ollama 的模型仓库、Hugging Face，或者 LM Studio 自己的服务器。
  • 打开应用：Ollama 没有对外连接。LM Studio 首次启动下载了约 172 MB 的推理引擎，之后每次约 1 MB。 Pinku 在加载已安装的模型时向 huggingface.co 发出了四个小请求。
  • 闲置：Ollama 和 Pinku 五分钟内什么都没发送。LM Studio 在一次聊天后不久，向自己的服务器建立了约 30 个连接。

2026年10月20日在一台 Mac 上测得。“没有”表示在整个阶段中，nettop 没有显示该应用的进程连接到 Mac 之外的任何地址； 到 127.0.0.1 的连接（应用与自身通信）不计算在内。

Ollama

我们使用的是 Homebrew 版本，以后台服务运行。启动时，它在 127.0.0.1:11434 上开启服务，并启动一个与之通信的辅助进程，都是本地的。 ollama pull qwen3:0.6b 连接了 registry.ollama.ai，然后从 Cloudflare 存储下载了 524 MB。 用 ollama run 提问时只与本地服务通信，之后五分钟也是如此。这只适用于命令行版本： 从 ollama.com 下载的 Ollama 应用有自己的窗口和更新程序，我们没有测试。

LM Studio

首次启动时，在我们还没做任何操作之前，LM Studio 就从 extensions.lmstudio.ai 下载了约 172 MB。 它自己的下载记录列出了内容：llama.cpp 引擎、一个 Python 运行环境和一个名为 harmony 的工具。之后每次启动从 lmstudio.ai 地址获取约 1 MB。

模型下载并不是直接连接 Hugging Face。我们请求了 mlx-community/Qwen3-0.6B-4bit，LM Studio 的记录显示所有文件都来自 search.lmstudio.ai/v1/hf-proxy/…，这是 LM Studio 运营的代理。未改动的设置文件中是 "useHFProxy": true。也就是说，LM Studio 的服务器能看到你下载了哪些模型。但这并不意味着它们能看到你的聊天。

我们无法用工具操作 LM Studio 的聊天窗口，所以通过 LM Studio 自带、使用同一引擎的 lms chat 命令聊天。 用默认命令时，LM Studio 在回答期间从 lmstudio.ai 获取了模型目录：接收约 150 KB，发送 12 KB。加上 --dont-fetch-catalog 选项后，同样的问题没有产生任何对外连接。随后闲置的五分钟里，LM Studio 在第 45 到 60 秒之间 向 lmstudio.ai 地址建立了约 30 个连接（接收 3 MB，发送 31 KB，每个连接发送不到 3 KB），之后再无连接。本地服务只监听 127.0.0.1。

Pinku

Pinku 是一款在设备上运行开放模型的 iPhone 和 Mac 应用。Pinku 把聊天记录保存在设备上，不会离开设备。Apple 隐私标签中，Pinku 只列出了购买记录和一个用于 Pinku Pro 的匿名 ID。 Mac App Store 上的版本是 1.0.7。 测试用的 Mac 上没有安装 Pinku，因此我们从源代码编译了 1.0.7，并用单独的应用标识运行，让它像全新安装一样启动。

  • 首次启动、没有模型：60 秒内没有任何连接。
  • 下载最小的模型（Qwen3 0.6B，0.4 GB）：向 huggingface.co 请求模型文件，权重来自 Hugging Face 在亚马逊服务器上的存储。 我们的记录在下载开始 22 秒后才启动，捕获了约 347 MB；应用的网络缓存中只有 huggingface.co 的地址。
  • 已安装模型后打开：七秒内向 huggingface.co 发出四个 HTTPS 请求，接收约 35 KB，发送 23 KB。 响应是“304 Not Modified”：Pinku 在检查 Mac 上的模型文件是否仍是最新版本。请求中包含模型名称，Hugging Face 能看到这台 Mac 的 IP 地址。请求中没有聊天内容。
  • 聊天（一个问题，约 85 秒得到回答）：没有连接。
  • 闲置 5 分钟：没有连接。

Pinku 的 App Store 描述没有提到启动时的这项检查；这是我们在本次测试中发现的。购买 Pinku Pro 通过 Apple 自己的系统进程与 Apple 通信； 用这些工具无法把这部分流量归属到某一个应用，所以购买不在结果之内。

测量方法

  1. 一台 Apple 芯片的 Mac，macOS 26.7.1，Wi-Fi，2026年10月20日。没有更改安全设置，没有使用管理员密码，没有授予新权限。
  2. 用 macOS 自带的网络监视工具 nettop，每秒记录所有进程的所有套接字，包括远程地址和收发字节，只保留各应用的进程。
  3. 用 lsof 查看每个应用监听的端口。
  4. 主机名来自应用自己的记录（Pinku 的网络缓存、LM Studio 的下载记录）、macOS 日志，以及对地址的 DNS 查询。
  5. 每个应用四个阶段：打开（60 到 90 秒）、下载最小的模型、一个问题（Write three short sentences about the sea）、打开应用闲置五分钟。
  6. 测试结束后，我们删除了 LM Studio、下载的模型和我们编译的 Pinku。

我们看不到的部分

  • 连接的内容。连接是加密的。不抓包（需要管理员密码）只能看到数据去了哪里、有多少，看不到具体内容。
  • 极短的连接，在一秒内打开又关闭，nettop 可能漏掉。对 Pinku 和 LM Studio，应用自己的日志和缓存与 nettop 的结果一致。
  • iPhone。以上都是在 Mac 上测的。iOS 上的应用无法用这种方式检查。
  • 更长的时间。五分钟闲置不等于一天。每天检查一次更新的应用不会在测试中出现。
  • 其他应用。我们只测了三款。Jan、GPT4All、Msty 等不在本次测试中。

自己如何检查一个应用

打开“终端”，在使用应用时运行 nettop -P -L 0 -s 1 -n；每一行显示一个进程及其收发字节。 只看一个应用，可以用 nettop -p 加进程名。查看监听端口用 lsof -nP -iTCP -sTCP:LISTEN。 在聊天时和下载模型时各做一次，就能看到本文所说的区别。

问题到达云端聊天机器人之后会被保存多久，请看 ChatGPT、Claude、Gemini 等会保存什么，删除有什么用。

常见问题

Ollama 会把我的聊天发到网上吗？

在我们的 Mac 测试中（Homebrew 版 Ollama 0.20.2，2026年10月20日）不会。聊天和闲置五分钟只有到 127.0.0.1 的本地连接。下载模型时会连接 registry.ollama.ai。

不下载东西时 LM Studio 会联网吗？

会。在我们的测试中，它首次启动下载了约 172 MB 的引擎，之后每次启动约 1 MB，用 lms 命令聊天时获取了模型目录，闲置时还向自己的服务器建立过约 30 个连接。我们没有看到传送聊天内容的连接。

LM Studio 能看到我下载了哪些模型吗？

默认设置下能：从 Hugging Face 的下载经由 search.lmstudio.ai/v1/hf-proxy，设置文件中 useHFProxy 为 true。

Pinku 聊天时会发送什么吗？

不会。Pinku Mac 版 1.0.7 在聊天和闲置时都没有连接。它会连接 Hugging Face 下载模型，1.0.7 版在加载已安装的模型时也会连接，用于检查模型文件。

怎样查看 Mac 上的应用发送了什么？

使用应用时在“终端”中运行 nettop -P -L 0 -s 1 -n。它会列出每个进程收发的字节，不需要管理员密码。

来源与工具

  • Apple，macOS 26.7.1 中 nettop 和 lsof 的手册（man nettop、man lsof）。
  • Ollama 0.20.2，通过 Homebrew 安装（brew install ollama）。
  • LM Studio 0.4.26，Homebrew cask，从 lmstudio.ai 下载官方安装包。
  • Pinku Mac 版 1.0.7，由源代码编译；App Store 隐私标签为2026年10月20日所见。
  • 模型：qwen3:0.6b（Ollama）和 mlx-community/Qwen3-0.6B-4bit（LM Studio 和 Pinku）。
